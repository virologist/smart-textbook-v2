# gap-types.md — 缺口类型学（gap_type 枚举 SSOT）

> 版本：v1.0 ｜ 日期：2026-11-02 ｜ 批次：B3 缺口闭环（架构设计 §3.2）
> 定位：**缺口类型的唯一权威枚举**。任何 agent 判定「这是哪一类缺口」时，只许引用本表，不得自造类型名。
> 红线 P-2：本文件属通用层，**禁止出现任何教材专用值**（教材名/疾病名/物种名/机构名）——示例一律用 `{{placeholder}}`。

---

## 1. 为什么需要类型学

缺口（gap）不是同质的：「缺一个数值」和「缺一张鉴别表」的检索路径、审批优先级、回填形态完全不同。若不分类，缺口台账退化为散文清单，审批无法排序，检索无法分派。

本表提供三个维度：**检索路径**（找什么）· **回填形态**（填回去是什么）· **审批权重**（先批哪个）。

## 2. gap_type 枚举（七类）

| gap_type | 中文名 | 检索路径 | 回填形态 | 审批权重 |
|---|---|---|---|---|
| `data_value` | 数据值缺口 | 权威统计源 / 数据库 | 数值 + 出处 + 单位 | **P0**（阻塞交付） |
| `data_series` | 数据序列缺口 | 时间序列 / 流行病学监测 | 表格 / 序列 + 出处 | **P0** |
| `literature_claim` | 文献论断缺口 | 学术库（英文优先 + 中文双轨） | 命题 + PMID/DOI | **P1** |
| `chart_data` | 图表数据缺口 | 同 `data_series`，附绘图需求 | 数据列 + 图型意图 | **P1** |
| `case_example` | 案例缺口 | 教材案例库 / 生产实践报道 | 案例叙述 + 情境 | **P2** |
| `terminology` | 术语缺口 | 学科术语表 / 权威规范 | 术语 + 定义 + 权威源 | **P2** |
| `mechanism` | 机制缺口 | 机制研究 / 综述 | 机制链条描述 + 出处 | **P1** |

> **枚举封闭**：上表七类之外不得新增。新增类型须改本文件 + 改 `scripts/check_gap_flow.py` 的枚举校验 + 同步 `skills/gap-driven-loop/SKILL.md`，三处同步缺一即视为未生效。

## 3. 优先级（priority）与审批权重的关系

审批权重是**缺省优先级**，可在章节层显式覆盖（写入 `gaps.md` 的 `priority` 字段）。

| priority | 含义 | 典型 gap_type | 审批行为 |
|---|---|---|---|
| `P0` | 不补则章节不可交付 | data_value / data_series | 必批（超 10 个时优先保留） |
| `P1` | 不补则章节质量显著受损 | literature_claim / chart_data / mechanism | 常规批 |
| `P2` | 可延后到下一轮 | case_example / terminology | 不足 3 个时扩批（见 §5） |

## 4. 每类缺口的判定要点

### data_value（数据值缺口）
- **判据**：正文需要一个**具体数值**（率、量、阈值、剂量）但无出处
- **典型误判**：把「需要举例说明」误标为 data_value → 应为 case_example
- **回填必须含**：数值 + 单位 + 出处锚 + 适用范围

### data_series（数据序列缺口）
- **判据**：需要**一组**按维度排列的值（按年份/按地区/按品种）
- **与 data_value 的区别**：单个数 vs 序列
- **回填必须含**：完整序列 + 各点出处 + 时间/空间口径

### literature_claim（文献论断缺口）
- **判据**：需要一条**可被文献支持/证伪**的命题，且当前无 PMID/DOI 支撑
- **回填必须含**：命题 + PMID 或 DOI + 该文献确实支持此命题（须核验，不得「主题相关即算」）

### chart_data（图表数据缺口）
- **判据**：正文/图位需要**成图的数据列**
- **回填必须含**：数据列 + 建议图型 + 是否需溯源图（对应 B4 的 figure-registry）

### case_example（案例缺口）
- **判据**：需要**具体情境的案例**（真实事件、生产案例、病例）以支撑教学
- **回填必须含**：案例情境 + 出处（真实案例须可核验；教学案例须标明为教学编写）

### terminology（术语缺口）
- **判据**：需要**规范术语的定义**（尤其专业术语、缩写、量纲）
- **回填必须含**：术语 + 定义 + 权威源（学科术语表 / 国家标准 / 权威手册）

### mechanism（机制缺口）
- **判据**：需要解释**为什么/如何发生**的因果链条
- **回填必须含**：机制各环节 + 每环出处（不得只给结论性断言）

## 5. 审批规则（3-10 规则，与 §3.2 设计一致）

| 情形 | 处置 |
|---|---|
| 待审缺口总数 > 10 | 按 priority 截断至 10（P0 全留，其余按类型权重 + 出现顺序） |
| 待审缺口总数 ∈ [3,10] | 全批 |
| 待审缺口总数 < 3 | **扩批**至相邻缺口（从本章其他未列缺口或下一优先级补足），仍不足则本轮只批现有数并标注「本轮不足 3 个」 |
| 已批 10 个且仍有未批 | 其余标 `deferred`（延后），不得丢弃 |

审批结论三态：`approved`（进入检索）/ `rejected`（不检索，附理由）/ `deferred`（延后到下一轮）。

## 6. 状态机（缺口生命周期）

```
proposed  ──审批──▶ approved ──检索──▶ retrieved ──回填──▶ filled ──核验──▶ resolved
    │                   │                                      │
    │                   └──▶ rejected（附理由）                ├──▶ partially_resolved
    └──▶ deferred（延后下一轮）                                  │
                                                               └──▶ unresolved（返修重试）
```

- **合法流转**：proposed → {approved | rejected | deferred}；approved → retrieved；retrieved → filled；filled → {resolved | partially_resolved | unresolved}
- **禁止流转**：`proposed → filled`（跳过审批）、`approved → resolved`（跳过检索）、`unresolved → resolved`（未经返修直接关闭）
- `unresolved` 累计计数参与 L1 终止条件（`count(unresolved) == 0`）

## 7. 标签形态（正文 ↔ 台账双向可查）

| 标签 | 含义 | 台账对应 |
|---|---|---|
| `[需补数据·{{ch##}}-g{{NN}}]` | 缺口待补（检索前标记） | gaps.md 中 status ∈ {approved, retrieved} |
| `[已补·{{ch##}}-g{{NN}}]` | 已回填且带证据锚 | status = filled / resolved |
| `[待核实·{{ch##}}-g{{NN}}]` | 已回填但证据不足以定论 | status = partially_resolved / unresolved |

**兼容既有标签**（B0-Q6 裁决）：旧形态 `[待核实]` / `[估]` / `[实]` **继续有效**，语义不变；新流程只对**新增缺口**使用带编号形态。既有标签与编号标签可并存于同一章节。

**编号唯一性**：`{{NN}}` 在**章节内唯一递增**（两位补零，起始 01）。跨章节可重号（`ch01-g03` 与 `ch02-g03` 互不冲突）。

## 8. 与既有体系的关系

| 既有物 | 关系 |
|---|---|
| `[实]` / `[估]` / `[待核实·reason=…]` | **并存**。新标签是缺口专用形态；旧标签是事实级证据强度标注 |
| `references/rule-engine/base_rules.yaml#retrieval_gate_config` | 三轨并行检索门禁；本表定义的是**检索什么**（类型），不重复定义**怎么检索**（轨道） |
| `agents/chief-editor/protocol.md` H15 螺旋 | H15 是 `[待核实]` 的既有兜底链路；新缺口闭环是**前置**机制（缺口在起草期即登记，不等审查期才发现） |
| 图表登记表（figure-registry） | chart_data 类缺口的回填去向之一；该登记表规范由图表流水线批次落地 |
