# 架构设计 · smart-textbook-v2

> 六层架构（Harness = E/T/C/S/L/V）+ 架构范式 P 的落位说明。
> 本包是**运行时系统**，不是文档集合：每个架构承诺都有一个可执行的守护脚本。

---

## 1. 范式 P（五条强制原则）

| # | 原则 | 落点 | 守护 |
|---|---|---|---|
| P1 | **单一权威**（每个事实只写一份，其余引用不复述） | `references/rule-engine/state_machine_v2.yaml`（相位）、`field_registry.yaml`（字段语义） | `check_phase_consistency` · `test_contract_sync.py` |
| P2 | **基因层学科中立**（通用层零教材专用值） | `references/` `skills/` `scripts/` 全部通用 | `check_manifest.py` M11 |
| P3 | **声明与实现解耦校验**（文档说 X 由 Y 做，Y 必须真有 X） | 各 skill 的「相关规范」段 | `check_declaration` 式反查 · `scripts/gates/g4_rules_files.py` |
| P4 | **破坏样本优先**（每个判据配负向样本自证能拦） | 全部校验器 `--probe-negatives` | 每个脚本自带探针 |
| P5 | **退化不阻塞、违规必红**（存量 baseline 豁免，新增违规即刻红） | `scripts/gates/_baseline.json`（sha1 精确哈希） | g1–g5 各自的 baseline 机制 |

## 2. 六层架构

### E · 编排层（Orchestration）
- **谁**：主理人 `smart-textbook-v2-team-lead`
- **落点**：`agents/smart-textbook-v2-team-lead.md` · 13 态推进 · 委派六点契约 · 缺口审批 · 门禁调度
- **状态机**：唯一权威 = `references/rule-engine/state_machine_v2.yaml`

### T · 工具与技能层（Tooling）
- **落点**：`skills/`（7 个）· `scripts/`（12 个可执行门禁 + gates/ 5 组）
- **技能**：rule-inheritance · gap-driven-loop · citation-verify · retrieval-gate · wiki-query · knowledge-deposit · vault-search
- **纪律**：能力必须有可执行载体（shell hook 不算——它需要 hook 触发，而 hook 可能从未生效）

### C · 上下文隔离层（Context）
- **规则层 vs 工作区分离**：包内 = 规则与资产；工作区 = 教材实例与章节内容
- **双根语义**：`PKG_ROOT`（包根，规则层恒定在此）· `WORKSPACE_ROOT`（被检工作区，`STT_WORKSPACE` 注入）
- **渐进式加载**：先读 `retrieval/INDEX.md` → 按需加载产物；先读 registry → 按需加载图文件

### S · 状态与存储层（State）
- **状态外置**：进度与缺口在 `章节/{ch##}/` 的文件里，不在对话里
- **三层规则存储**：基因层（包内）→ 教材层（工作区）→ 章节层（工作区）
- **统一日志**：12 字段 JSONL，章节级 + 项目级双落点（`references/logging-spec.md`）

### L · 审核与门禁层（Loop / Gate）
- **门禁**：规则层 V1–V7 · 缺口层 G1–G5 · 图表层 F1–F7 · 契约层 M1–M12 · 通用门禁 35 判据（G1–G5 组）
- **人工门**：规则差异报告确认（主编排 → 用户）· `_derived` 衍生值确认 · 交付终审
- **准入**：门禁以**脚本退出码**为准，不接受自评

### V · 验证层（Verification）
- **独立验证**：审查官独立于撰写师；测试工程师独立于编码者
- **对抗探针**：每个校验器自带负向样本集（`--probe-negatives`），自证能拦
- **可回滚**：每批次独立 commit；重编号出 rename_map（JSON，可反向回滚）

## 4. 三层规则继承（本包核心创新）

```
包内 references/rule-engine/     ① 基因层（抽象·通用·可实例化）
        │  base_rules · field_registry · state_machine
        ↓ 继承 + 用户审核定制 + 联网检索衍生
工作区 <教材>/00-教材规则/          ② 变异层（教材实例化 · 学科专用值在此）
        ↓ 继承 + 章节级覆盖（_local_overrides）
工作区 <教材>/章节/{ch##}/          ③ 实例层（章节微调）
```

**三态**：`inherit` 继承 · `override` 变异（用户设定）· `derive` 衍生（**联网检索衍生，必附证据，待用户确认**）

**为什么抽象边界划在「基因层 ↔ 教材层」**：实测两本教材的 `textbook_rules.yaml` 共有键仅 9/17，学科专用值占比近 100%——教材层**不能**作基因层；而系统规则层 48 文件用领域词表扫描**零命中**，基因层抽象成立。

## 5. 已知边界与不做清单

| 项 | 说明 |
|---|---|
| 教材实例不打包 | 实例在**包外工作区**（含教材专用值，打包即违反 P2） |
| 旧 `.claude/` 架构 | 保留在 tb-writer 仓归档，不进包 |
| `hooks/` `commands/` 目录 | **禁止**（WorkBuddy 校验 error 级）——门禁一律走 CLI + CI |
| 绘图库 | 沿用 ipynb + matplotlib，不引入新绘图栈 |
| 多包发布 | 不做（单包 + 学科 profile） |
